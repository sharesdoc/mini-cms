# I-质量控制指导

> 由 aud 产出的质量底线；dev/tst/rev 据此把关。

## 1. 需求覆盖门禁
- A §2 每条 P0 需求必须可追溯到 X 任务 + 测试用例 + 代码实现。
- 重点核查「级别硬上限 3」「伪删除」「可见性跨级禁止」「群禁言」「11 位 ID」「admin 写死口令」六处易漏点。

## 2. 安全闸门（强制）
- 鉴权：除 register/login，所有接口须经 AuthInterceptor；缺失/失效 token → 40101。
- 越权：普通客户不可访问 admin 接口（40301）；不可查非自己下游的客户详情；群成员管理仅群主。
- 注入：MyBatis 一律 `#{}` 占位，禁止 `${}` 拼接用户输入（动态排序白名单）。
- 密码：BCrypt 存储；admin 口令仅代码常量比对，不入库不日志。
- 敏感信息：UserVO 脱敏（不含 password）；日志不打印密码/idcard 全量。
- 跨域：仅放行 web 前端来源（dev 5173 / 配置的 prod 域）。

## 3. 代码质量
- 分层清晰：controller 不含业务逻辑；service 承载领域规则；mapper 只 SQL。
- 函数/参数/异常有中文注释（项目宪法 §2.2）。
- 统一异常 → 统一响应，禁止 controller 直接抛 SQL 异常到前端。
- 极简原则：不加 A-F 未要求功能（铁律 0）。

## 4. 已知风险/改进项（记入 J，本轮不阻塞）
- R1：Token 内存存储，重启失效；多实例需 Redis。（架构权衡）
- R2：idcard 仅做非空校验，未做格式/合法性校验（需求未要求）。
- R3：消息为轮询拉取，未用 WebSocket 实时推送（需求未要求实时）。
- R4：头像为色块索引，非图片上传（需求"设定头像"，设计原型用色块，按设计实现）。
