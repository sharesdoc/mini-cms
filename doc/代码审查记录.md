## 1. 发现项（按严重度）

### 🟡 important — 拓展指标并发竞态（CustomerService.expand:41/48-49）
**问题**：`me.quota` 采用「读-检查-写」(`meQuotaLeft = me.quota - 1; updateQuota(...)`)，非原子。两个并发拓展请求均读到 quota=1 → 都通过校验 → 都写入 quota=0，实际挂靠 2 个下游却只扣 1，**指标超卖**。
**影响**：违反 REQ-LVL-02「挂靠一个则指标 -1」的严格性；高并发下可突破指标上限。
**修复**：改为原子条件更新 `UPDATE cms_user SET quota=quota-1 WHERE id=? AND quota>0`，受影响行数=0 即视为无指标拒绝。

### 🟢 nit — 管理员无法浏览已伪删除客户以恢复
伪删除后客户从所有列表/树/详情消失（符合「隐藏」），`restore` 接口仅能按已知 ID 恢复。建议（非阻塞）：管理端增加「回收站」筛选查看 deleted 客户。记入 J。

### 🟢 nit — favicon 404
前端 index.html 未提供 favicon，控制台 404（无害）。建议补一个 svg favicon。

### 💡 suggestion — MyBatis StdOut 日志
application.yml `log-impl: StdOutImpl` 在生产冗长。建议仅 dev profile 开启。

## 2. 安全闸门核查（I §2）— ✅ 通过
- 鉴权：AuthInterceptor 拦截 /api/**，放行 register/login；无/失效 token→40101（已测）。
- 越权：普通客户调 admin 接口→40301、跨级查看→40301（已测）；群成员管理/禁言仅群主（hasOwner 校验）。
