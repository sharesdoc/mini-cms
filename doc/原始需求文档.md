编写一个客户拓展系统 这个系统的核心需求有下面这几个方面：

1. 支持用户注册和用户登录
2. 注册只需用户名和密码
3. 用户名默认为手机号，也可使用其他用户名
4. 手机号仅作为唯一 ID，无需发送短信验证
5. 注册输入框默认提示“用手机号注册”

用户有级别概念，分为一级用户、二级用户和三级用户。每个级别都有不同的权限，一级、二级和三级用户的权限各不相同。还有一个超级管理员，用户名默认为 admin，口令由部署配置提供。

超级管理员可以查看系统有多少用户，每个一级用户、二级用户、三级用户的详细信息，以及各个用户的相关状态等。超级用户无所不能，啥都能干。 

一级用户可以拓展下级，即二级客户。二级客户的数量由管理员在系统配置中设定，全系统统一。若用户被定义为一级用户，其可拓展的二级客户数量即遵循该系统设定。

二级客户也能拓展客户，他拓展的客户就是三级客户。二级客户能拓展三级客户的数量也是由系统设定。 

这套级别体系是相对的。客户刚进来时是普通客户，当拓展了一定数量的客户或达到一定业绩目标后，就可以升级。如果整个系统定义好，整个级别有 3 级，那么：
1. 最普通的用户就是第 3 级
2. 普通用户往上升就升为 2 级
3. 2 级再往上升就升为 1 级 
系统默认最大只支持三级用户，这是限死的，管理员也改变不了。最大三级，普通用户就是第三级用户。 
系统也可以设定为只支持二级，那么普通用户就是二级用户，往上升就升成一级用户。但是系统不能设置成三级以上的。系统也可以设置为一级用户，就是不存在级别。 

总之就是系统可以通过配置文件来设定系统支持的客户级别，注意啊不是管理员设定啊，是通过系统部署的时候通过配置文件来设定，设定之后那么所有的客户级别就按系统定死的这个级别机制来运行 除非修改系统部署的配置文件，可以扩大升级，比如说从二级升为三级 但是即使改配置文件也不能改成四级，这是绝对禁止的 代码逻辑里面就要把这个门槛写死，最多支持三级 

不管哪个级别的客户，都有一个默认的可拓展下游客户数量指标。一旦有客户挂靠到其名下，该指标数量自动减 1。 
系统管理员可以临时给某个客户提高他的指标数量，也就是他的下游客户的数量是可以提高的 
客户可以看到自己的下游客户，但不能看到下游客户的下游客户，不能跨级，只能看到自己名下的所有拓展客户 

客户可以看到自己的上级，每个客户只能有一个上级，不能有多个上级。 

客户注册登录之后，首先要完善个人信息，包括姓名、身份证号码、电话号码、家庭住址 客户第一次登录后，系统自动提示跳转到完善个人信息页面。若未完善，则持续提示。客户可关闭暂不填写，但只要未完成填写，每次登录都会提示，直至填写完毕。 

管理员可以点击查看所有客户，也可以按级别查看，比如所有一级客户。点击一级客户后，可以看到其下所有客户，支持继续点击进行深度搜索查看，也可以点击后退。 这里相当于有一个树状结构，可以深度优先或广度优先来查看，也可以后退。 点击客户就可以查看这个客户所有相关的信息

这个系统的名字就叫客户管理系统CMS 

系统要支持网页端和手机端的显示，最好是能适配手机端，而且手机端的展示效果要优先，优先手机端的展示效果的设计。 
换句话说是开发手机端的页面要适配电脑端

超级用户管理员对客户的删除操作做伪删除，其实就是做一个标记不显示。超级用户可以禁用、删除、激活客户账户

超级用户登录之后要看到一个统计报表页面，统计有多少用户？每天新增多少用户？

页面的设计风格可以采用阿里巴巴的橙色系设计风格 

系统页面支持中文和英文，也就是说要能支持国际化，用户可以点击切换语言

用户可以设定自己的头像

用户可以创建群组，可以通过对方的 ID 添加。注意，ID 不是登录用户名，而是系统生成的唯一 ID。 这个唯一的 ID 生成算法是随机生成一个 11 位的随机数字。注意啊，不是手机号，是系统随机生成的一个 11 位的数字，作为每一个用户的用户 ID。
用户添加这个 ID 之后，就可以看到自己的好友，然后可以看到好友的列表，点击好友可以发送消息，可以聊天
用户也可以建群，在好友列表中选择好友即可建群。只有群主可以添加或删除群成员。 群建立之后，大家都可以发言。群主可以设定禁言，让群其他人都不能发言，也可以设定群里面大家都可以发言。默认是大家都可以发言。 

创建群的时候，可以指定群的名字

目前只支持发文字，不管是和好友聊天还是在群里面发消息都只能发文字，不能发语音，不能发文件，只能发纯文本
