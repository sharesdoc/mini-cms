# A-系统需求文档

> 项目：客户管理系统 CMS（Customer Management System）
> 来源：`CMS-需求文档.md`（用户原始需求）+ 设计原型 `cms/CMS 客户管理系统.dc.html`
> 级别：主系统 | 版本：v1.0 | 日期：2026-08-02

## 1. 系统概述

客户拓展与社交管理系统 CMS，核心是**多级客户层级拓展体系**（最多 3 级，硬限制）+ **客户资料管理** + **站内即时通讯（好友/群组/纯文本消息）**。系统须支持 Web 端与移动端，**移动端展示效果优先**，采用阿里巴巴橙色系设计风格，支持中英文国际化切换。

### 1.1 角色

| 角色 | 标识 | 说明 |
|------|------|------|
| 超级管理员 | admin | 用户名默认为 `admin`，口令由部署环境注入；无所不能 |
| 一级客户 | level=1 | 最高级别（在三级体系下），可拓展二级客户 |
| 二级客户 | level=2 | 可拓展三级客户 |
| 三级客户 | level=3 | 普通客户（三级体系下的最底层） |

> 级别是**相对**的：系统部署时配置支持的级别数（1/2/3），普通客户即为最低级，逐级上升。**最大支持 3 级，代码层硬性写死，绝不支持 4 级及以上**。

## 2. 功能需求清单

### 2.1 账户与认证（AUTH）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| REQ-AUTH-01 | 支持用户注册和登录 | P0 |
| REQ-AUTH-02 | 注册仅需用户名和密码 | P0 |
| REQ-AUTH-03 | 用户名默认为手机号，也可用其他用户名；手机号仅作唯一 ID，无需短信验证 | P0 |
| REQ-AUTH-04 | 注册输入框默认提示"用手机号注册"；登录提示"手机号或用户名" | P1 |
| REQ-AUTH-05 | 超级管理员账号名默认为 admin，口令由部署配置注入，不进入源码 | P0 |
| REQ-AUTH-06 | 密码长度不少于 6 位；注册时需二次确认密码 | P0 |
| REQ-AUTH-07 | 注册时系统生成 11 位随机数字作为用户唯一 ID（非手机号） | P0 |

### 2.2 客户资料（PROFILE）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| REQ-PROF-01 | 客户须完善个人信息：姓名、身份证号、电话号码、家庭住址 | P0 |
| REQ-PROF-02 | 首次登录后系统自动提示跳转完善资料页；未完善则每次登录持续提示，可"暂不填写"关闭 | P0 |
| REQ-PROF-03 | 客户可设定自己的头像（设计原型为 8 色色块选择） | P1 |

### 2.3 客户层级与拓展（LEVEL）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| REQ-LVL-01 | 支持客户分级，最多 3 级，硬限制（部署配置文件设定，管理员不可改；改配置也不可超过 3 级） | P0 |
| REQ-LVL-02 | 每个级别有默认可拓展下游客户数量指标；挂靠一个则指标 -1 | P0 |
| REQ-LVL-03 | 管理员可临时给某客户提高指标数量 | P0 |
| REQ-LVL-04 | 客户只能看自己的下游客户，不能跨级、不能看下游的下游 | P0 |
| REQ-LVL-05 | 每个客户只能有一个上级 | P0 |
| REQ-LVL-06 | 拓展下游：输入对方 11 位系统 ID 挂靠到自己名下；对方需尚无上级；自己需有剩余指标；级别须符合（挂靠方级别=自己级别+1，且不超 maxLevel） | P0 |
| REQ-LVL-07 | 升级机制：当拓展下游数达到系统设定的升级门槛时自动升级（级别数-1，即向上靠） | P0 |
| REQ-LVL-08 | 各级默认拓展指标、升级门槛由系统设定（管理员可在系统配置页调整；级别数本身不可改） | P1 |

### 2.4 客户网络查看（NET）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| REQ-NET-01 | 管理员可查看所有客户，可按级别筛选（如所有一级客户） | P0 |
| REQ-NET-02 | 管理员点击某客户后可见其所有下游，支持继续深入查看与后退（树状结构，深度/广度遍历） | P0 |
| REQ-NET-03 | 提供列表视图与树形视图切换 | P1 |
| REQ-NET-04 | 普通客户仅看自己名下下游客户列表 | P0 |
| REQ-NET-05 | 点击客户查看其完整资料（含管理员操作入口） | P0 |
| REQ-NET-06 | 支持按姓名/ID/用户名搜索 | P1 |

### 2.5 管理员操作与统计（ADMIN）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| REQ-ADM-01 | 删除客户为**伪删除**（标记隐藏不显示，数据保留可恢复） | P0 |
| REQ-ADM-02 | 管理员可禁用、激活客户账户 | P0 |
| REQ-ADM-03 | 管理员登录后看到统计报表：总客户数、今日新增、每日新增趋势、级别分布 | P0 |

### 2.6 即时通讯（IM）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| REQ-IM-01 | 用户可通过对方 11 位系统 ID 添加好友 | P0 |
| REQ-IM-02 | 查看好友列表，点击好友发消息（单聊） | P0 |
| REQ-IM-03 | 可创建群组：输入群名，从好友列表选择成员建群 | P0 |
| REQ-IM-04 | 只有群主可添加/删除群成员 | P0 |
| REQ-IM-05 | 群主可设定全员禁言/允许发言（默认允许发言） | P0 |
| REQ-IM-06 | 群内所有人可发言（未禁言时） | P0 |
| REQ-IM-07 | 仅支持纯文本消息（无语音、无文件），单聊与群聊均如此 | P0 |

### 2.7 非功能需求（NFR）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| REQ-NFR-01 | 支持 Web 端与移动端，移动端展示优先，开发移动端页面适配电脑端 | P0 |
| REQ-NFR-02 | 阿里巴巴橙色系设计风格 | P1 |
| REQ-NFR-03 | 支持中英文国际化，用户可切换语言 | P0 |

## 3. 约束与边界

- **级别硬上限**：代码层硬性写死最多 3 级，任何配置/接口均不可突破（REQ-LVL-01）。
- **ID 生成**：11 位随机数字，系统生成，非手机号（REQ-AUTH-07）。
- **不使用物理外键**：依赖关系由应用层控制（项目宪法 §2.2）。
- **口令值规范**：admin 口令为 shasum 输出的 40 位十六进制串（项目宪法 §2.2）。
- **技术栈**：JDK 21、Spring Boot、MyBatis、MySQL 8（项目宪法 §2.2）。
- **范围外**：语音消息、文件传输、短信验证码、支付、推送通知——明确不做。

## 4. 验收标准（关键）

1. admin 用写死口令可登录并看到统计报表。
2. 普通客户注册→登录→被提示完善资料→完善后不再提示。
3. 一级客户输入下游 11 位 ID 拓展成功，指标 -1；达门槛自动升级。
4. 管理员可在树形视图逐级深入查看客户并后退。
5. 伪删除后客户从列表消失但数据可恢复。
6. 添加好友→建群→单聊/群聊发文字消息；群主禁言后他人无法发言。
7. 中英文切换生效；移动端与桌面端均可用。
8. 配置 maxLevel=4 时被强制限制为 3（代码硬限制验证）。
