## 2. 需求描述

用户要求把现有项目整理为适合发布到 GitHub 的开源项目，具体包括：

1. 删除或替换源码、配置、数据库脚本、文档、日志和构建产物中的隐私信息、真实个人资料、本机路径、固定凭据和运行痕迹。
2. 让独立数据库导出脚本与当前源码中的表结构、种子数据和字段保持一致，并使用匿名演示数据。
3. 增加标准 README，说明项目用途、技术栈、目录结构、环境要求、启动方式、数据库初始化、测试和安全注意事项。
4. 不改变核心业务功能；不把真实数据继续作为公开演示数据；不在 README 或前端展示真实口令。

## 3. 需求分析

当前项目没有根目录 README，已有配置和文档包含数据库口令、管理员口令，数据库导出包含姓名、手机号、身份证号、住址和真实感聊天内容；日志和构建产物也不适合作为源码发布内容。`dbs/cms-database.sql` 与 `svc/src/main/resources/schema.sql`、`data.sql` 的来源和内容不同，不能直接把旧导出文件发布出去。

本任务属于一次开源发布前的资料和数据边界整理，影响配置加载、数据库初始化、演示登录说明和部署文档。管理员口令改为环境变量后，开发者需要显式设置演示凭据；匿名种子数据只用于本地演示，不代表生产数据。

## 4. 设计方案

【最优解】以当前源码中的 `schema.sql` 和 `data.sql` 作为数据库权威来源，重建 `dbs/cms-database.sql` 为结构加匿名种子的单文件脚本；配置中的数据库凭据和管理员凭据全部改为环境变量，并保留安全的空值或占位默认值；清理日志、生成的 JAR、本机配置和真实资料；新增 README 和更完整的忽略规则。

- 数据库：表结构与当前 MyBatis 映射、源码初始化脚本一致；示例用户使用明显虚构的姓名、号码、地址和消息内容。
- 凭据：不把数据库密码、管理员密码写入仓库；README 只说明如何通过环境变量传入，不提供可复用的真实口令。
- 文档：保留业务设计文档，但移除真实凭据和个人资料，将演示账号改为环境变量说明。
- 发布边界：不删除源码、设计文档和测试代码；删除运行日志、安装产物和已生成二进制，避免将本机状态带入 GitHub。

总结：先把仓库里的真实资料和固定口令拿掉，再用匿名数据重做数据库脚本，最后补齐 README。这样项目可以公开，但使用者需要自己提供数据库和演示账号配置。

## 5. 关联影响

- 后端配置和启动脚本的凭据读取方式会变化，启动文档和数据库初始化脚本必须同步。
- 前端登录页不能继续展示固定管理员口令；演示账号提示改为环境变量配置说明。
- 数据库脚本变更会影响首次初始化和集成测试数据，但表名、字段和业务接口保持不变。
- 删除运行日志和 JAR 不影响源码构建；新增忽略规则防止这些文件再次进入发布包。
- 本任务不负责重新设计认证机制、不负责补充生产部署平台、不负责发布 GitHub 仓库本身。

## 6. 功能测试

1. 使用匿名数据库脚本初始化空 MySQL，确认六张业务表创建成功，种子数据只包含虚构内容。
2. 使用环境变量启动后端，确认数据库连接、注册、登录和鉴权接口正常。
3. 不设置凭据时检查启动行为和错误提示，不得回退到仓库内的真实密码。
4. 执行后端和前端已有测试，确认字段、接口响应和页面登录流程不因数据脱敏而破坏。
5. 全文扫描源码和发布文件，确认不再出现数据库密码、管理员固定口令、本机绝对路径、手机号、身份证号、住址和真实聊天内容。
6. 检查 README 中的命令、端口、环境变量和目录路径与实际项目一致。
